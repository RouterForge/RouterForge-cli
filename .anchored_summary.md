# Session Summary

## Goal
Fix execution reliability so RouterForge can actually build software.

## Changes Made

### 1. Execution creates real source files (`micro_agent.go`)
- Added `ProjectDir` field to `Context`
- Changed `TaskRunner.Execute` to:
  - Use `FILE: <path>` format in LLM prompt, asking model to output filenames
  - Parse `FILE:` sections from response and write to project directory
  - Fall back to `inferFilename()` heuristic when no `FILE:` prefix
- Files are now written to the actual project directory with proper names (e.g., `main.go`, `internal/handler/routes.go`)

### 2. Plan/build disconnect (`build.go`, `head_manager.go`)
- Extracted `applyPlan()` from `Design()` so it can be reused
- Added `RestorePlan()` to restore a plan from saved artifact without LLM calls
- Added `projectDir` field and `SetProjectDir()` to `HeadManager`
- `build.go` now loads `plan.json` from `.routerforge/artifacts/` first, falling back to `Design()` only if no saved plan exists

### 3. Review gates detect failures (`head_manager.go`)
- `Review()` now counts total/failed tasks across all agents
- Fail gates: if 0 tasks executed → error; if >50% failures → error

## Key Principles
- Always save plans to `.routerforge/artifacts/plan.json` (already existed via `savePlanArtifact`)
- LLM outputs are parsed for `FILE:` prefix; no prefix → heuristic filename
- Build is distinct from Plan: build loads saved plan and executes it
